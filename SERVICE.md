# Сервис рекомендаций

Сервис читает результаты расчёта из трёх файлов:

- `recommendations.parquet`: `user_id`, `item_id`, `score`, `rank`;
- `top_popular.parquet`: `item_id`, `score`, `rank`;
- `similar.parquet`: `item_id_1`, `item_id_2`, `score`, `rank`.

По умолчанию файлы хранятся в `data/recommendations/`. Если их ещё нет,
сервис один раз скачивает их из `recsys/recommendations/` персонального
S3-бакета через функции из `storage.py`. Уже скачанные файлы повторно не
загружаются. Для обновления результатов нужно остановить сервис и заменить
локальные файлы новыми.

Параметры задаются переменными окружения:

```bash
export S3_BUCKET=<имя-бакета>
export AWS_PROFILE=<имя-настроенного-профиля>
export S3_ENDPOINT_URL=https://storage.yandexcloud.net
```

`AWS_PROFILE` можно не задавать, если доступ к S3 уже настроен другим
стандартным способом. Ключи доступа в репозиторий добавлять не нужно.
При необходимости локальный каталог можно изменить через
`RECOMMENDATIONS_DIR`, а префикс в бакете — через `S3_RECOMMENDATIONS_PREFIX`.

В Windows можно использовать уже сохранённое подключение CS Browser через
его [официальный командный интерфейс](https://s3browser.com/s3cmd.aspx).
В этом случае задайте имя существующего аккаунта. Ключи из настроек
программы копировать в Python не требуется:

```powershell
$env:S3_BUCKET = '<имя-бакета>'
$env:S3_BROWSER_ACCOUNT = '<имя-аккаунта-CS-Browser>'
$env:S3_BROWSER_CLI = 'C:\Program Files\CS Browser\s3browser-cli.exe'
```

Если `S3_BROWSER_ACCOUNT` задан, `storage.py` использует CS Browser;
иначе работает обычный вариант boto3. `S3_BROWSER_CLI` можно пропустить,
если программа установлена по указанному выше стандартному пути.

Запуск из каталога проекта:

```bash
python -m uvicorn recommendations_service:app --host 127.0.0.1 --port 8000
```

Примеры запросов:

```bash
curl -X POST 'http://127.0.0.1:8000/recommendations?user_id=1&k=20'
curl -X POST 'http://127.0.0.1:8000/similar_items?item_id=11&k=10'
curl 'http://127.0.0.1:8000/health'
curl 'http://127.0.0.1:8000/stats'
```

Для известного пользователя возвращаются персональные треки, для
неизвестного — популярные. Порядок определяется `rank`. Повторные треки
удаляются; в списке похожих треков сам исходный трек исключается. Размер
ответа ограничен `k`, допустимые значения — от 1 до 100. Если доступных
треков меньше, сервис возвращает более короткий список.

Файлы не загружаются целиком в pandas. DuckDB читает Parquet с фильтром по
пользователю или треку. Так расход памяти ограничен, но время ответа зависит
от расположения строк в файлах и скорости диска. Для прототипа этого
достаточно; файлы желательно сохранять в порядке `user_id, rank` и
`item_id_1, rank` соответственно. Запросы к одному соединению выполняются
последовательно, поэтому это не вариант для большой промышленной нагрузки.

Проверка на небольших искусственных данных, без обращения к S3:

```bash
python test_service.py
```

Тесты проверяют персональные рекомендации, замену для неизвестного
пользователя, порядок, лимит, удаление дубликатов, похожие треки и ошибки
параметров. Временные Parquet-файлы создаются в `work/service_tests/` и
удаляются после проверки. Для тестов нужен `httpx==0.27.2`, совместимый с
версией FastAPI в проекте.

После завершения полного расчёта можно проверить настоящий запущенный сервис.
Все Parquet-файлы должны быть готовы и закрыты процессом расчёта. Сервис и
проверка должны читать один и тот же каталог рекомендаций.

```bash
python test_service.py --live --url http://127.0.0.1:8000 --data-dir data/recommendations --output service_test_results.json
```

Команда выбирает существующего пользователя и трек из готовых файлов,
сравнивает HTTP-ответы с сохранёнными рекомендациями и проверяет популярную
выдачу для нового пользователя. Дополнительно проверяются похожие треки,
неизвестный трек, ошибка для `k=0`, `/health` и изменение счётчиков `/stats`.
В JSON записываются фактические ответы, HTTP-статусы и задержки запросов.
Код завершения — `0`, если все проверки прошли, и `1` при ошибке.

Параметры `--url`, `--data-dir` и `--output` необязательны: в примере указаны
их значения по умолчанию. Обычный запуск без `--live` по-прежнему выполняет
восемь тестов на искусственных данных и не обращается к S3 или HTTP-сервису.
