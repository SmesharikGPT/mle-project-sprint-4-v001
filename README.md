# Рекомендации музыкальных треков

Прототип рекомендательной системы: популярные треки, персональные рекомендации ALS, похожие треки и ранжирование кандидатов с помощью CatBoost. Основной расчёт находится в `recommendations.ipynb`, выдача готовых рекомендаций — в `recommendations_service.py`.

## Подготовка окружения

Используется Python 3.9–3.11 в Linux или Python 3.11 в Windows. Курс также разрешает выполнение на своём компьютере; для этой работы используется Windows с 32 ГиБ памяти. Исходные файлы занимают около 1,3 ГБ. События обрабатываются через DuckDB с временными файлами на диске, а матрица взаимодействий собирается пакетами. Для промежуточных данных желательно оставить не менее 30 ГБ свободного места.

В Linux:

```bash
git clone https://github.com/SmesharikGPT/mle-project-sprint-4-v001.git
cd mle-project-sprint-4-v001
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m ipykernel install --user --name music-recsys --display-name 'Python (music-recsys)'
```

В Windows, из PowerShell:

```powershell
git clone https://github.com/SmesharikGPT/mle-project-sprint-4-v001.git
cd mle-project-sprint-4-v001
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m ipykernel install --user --name music-recsys --display-name 'Python (music-recsys)'
```

FAISS используется для приближённого поиска кандидатов по векторам ALS. В зависимостях версии для Linux и Windows указаны отдельно. Все параметры моделей и поиска фиксированы; подбор гиперпараметров не проводится.

## Доступ к S3

Используется персональный бакет Yandex Object Storage и уже настроенные ключи в стандартной цепочке учётных данных boto3. Ключи не нужно записывать в ноутбук или репозиторий.

```bash
cp .env.example .env
```

В `.env` укажите `S3_BUCKET` и при необходимости `AWS_PROFILE`. Если используются переменные `AWS_ACCESS_KEY_ID` и `AWS_SECRET_ACCESS_KEY`, строку `AWS_PROFILE` следует убрать. Затем загрузите настройки в окружение:

```bash
set -a
source .env
set +a
```

Профиль должен иметь доступ к чтению и записи объектов в личном бакете. Перед расчётом ноутбук проверяет подключение. Локальные данные, `.env` и модели исключены из Git.

Если в Windows уже настроен CS Browser, можно пользоваться его сохранённым аккаунтом через официальный `s3browser-cli.exe`. Ключи при этом не читаются из программы и не копируются в проект. Вместо AWS-профиля задайте:

```powershell
$env:S3_BUCKET = '<имя личного бакета>'
$env:S3_BROWSER_ACCOUNT = '<имя сохранённого подключения CS Browser>'
```

По умолчанию CLI ищется в `C:\Program Files\CS Browser\s3browser-cli.exe`. Другой путь можно передать переменной `S3_BROWSER_CLI`. На Linux и без `S3_BROWSER_ACCOUNT` используется обычный boto3.

## Расчёт рекомендаций

```bash
python download_data.py
jupyter lab --no-browser
```

Откройте `recommendations.ipynb`, выберите ядро `Python (music-recsys)` и выполните все ячейки по порядку. В начале ноутбука сохранены исходники вспомогательных модулей и зависимости, чтобы его можно было перенести в Jupyter Hub одним файлом. Ячейка установки зависимостей должна выполняться до импортов.

Для последовательного запуска из терминала в активном окружении:

```bash
python run_notebook.py
```

В Windows та же команда с полным путём к интерпретатору:

```powershell
.\.venv\Scripts\python.exe -u run_notebook.py
```

Команда использует ядро `music-recsys`, выполняет ячейки с остановкой при первой ошибке и сохраняет вывод после каждой ячейки в `recommendations.ipynb`. Другое установленное ядро можно указать через `--kernel`. Отправлять на проверку нужно файл после успешного выполнения всех ячеек, с графиками и таблицей метрик.

В ноутбуке выполняются следующие шаги:

1. Проверка типов идентификаторов, обязательных полей, точных дубликатов и неизвестных атрибутов треков. Повторные прослушивания сохраняются.
2. Анализ активности пользователей, популярных треков и жанров, непрослушанных треков.
3. Сохранение подготовленных данных в S3 и повторная загрузка из S3 перед обучением.
4. Разделение событий: обучение до 16 декабря 2022 года, тест с этой даты. Ранжирование обучается на отдельном более раннем временном разбиении внутри обучающей части.
5. ALS, поиск похожих треков и ранжирование кандидатов. Для обучения ранжирования берётся воспроизводимая выборка пользователей; ограничение указано в ноутбуке. Финальные рекомендации рассчитываются для всех пользователей из событий.
6. Оценка трёх подходов на одинаковых тестовых пользователях. Определения recall, precision, coverage и novelty приведены рядом с таблицей результатов.

При рекомендации музыки разрешены повторные прослушивания. Поэтому знакомые пользователю треки не исключаются из кандидатов; новизна оценивается отдельно.

## Файлы результатов

| Путь в личном S3-бакете | Содержимое |
| --- | --- |
| `recsys/data/items.parquet` | Подготовленный каталог треков |
| `recsys/data/events.parquet` | Подготовленные события |
| `recsys/recommendations/top_popular.parquet` | Популярные треки |
| `recsys/recommendations/personal_als.parquet` | Персональные рекомендации ALS |
| `recsys/recommendations/similar.parquet` | Похожие треки |
| `recsys/recommendations/recommendations.parquet` | Итоговые рекомендации после ранжирования |

Локальные копии находятся в `data/`. Файлы рекомендаций записываются батчами. Крупные Parquet-файлы не добавляются в Git.

В `artifacts.json` сохранены ключи S3, число строк, схемы, размеры и SHA-256 файлов. Размеры всех шести объектов проверены в бакете. Для подготовленных данных также проверено совпадение SHA-256 после скачивания из S3.

## Результаты проверки качества

Тестовый период — 16–31 декабря 2022 года, 783 525 пользователей, `k=20`. Все показатели в таблице выражены долями.

| Метод | Recall@20 | Precision@20 | Coverage@20 | Novelty@20 |
| --- | ---: | ---: | ---: | ---: |
| Популярные | 0.00780 | 0.00518 | 0.00002 | 0.93937 |
| ALS | 0.02129 | 0.00772 | 0.01778 | 0.77558 |
| Ранжирование | 0.02312 | 0.00946 | 0.03220 | 0.85405 |

В этом временном разбиении ранжирование повысило recall и precision относительно ALS, а также расширило охват каталога. Точные значения сохранены в `metrics.csv`, определения метрик и выводы — в ноутбуке.

## Запуск сервиса

Если локальных файлов нет, сервис скачает их из настроенного личного S3-бакета при запуске.

```bash
python -m uvicorn recommendations_service:app --host 127.0.0.1 --port 8000
```

В другом терминале:

```bash
curl -X POST 'http://127.0.0.1:8000/recommendations?user_id=1&k=20'
curl -X POST 'http://127.0.0.1:8000/similar_items?item_id=1&k=10'
curl 'http://127.0.0.1:8000/health'
```

Для неизвестного пользователя выдаётся популярное. Для трека без рассчитанных соседей возвращается пустой список. Подробности API и схем Parquet описаны в `SERVICE.md`.

Проверки сервиса на небольших искусственных данных:

```bash
python -m unittest test_service -v
```

Тесты проверяют порядок и ограничение выдачи, дубликаты, популярный вариант для нового пользователя, похожие треки и обработку неверных параметров. Эти проверки не заменяют оценку качества моделей на тестовом периоде.

Проверка запущенного сервиса на рассчитанных файлах:

```bash
python test_service.py --live --url http://127.0.0.1:8000
```

Она сравнивает HTTP-ответы с реальными Parquet-файлами и сохраняет результаты в `service_test_results.json`.

После сохранения результатов и отправки проекта на проверку виртуальную машину следует остановить.
