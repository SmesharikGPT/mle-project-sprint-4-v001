# Рекомендации музыкальных треков

Прототип рекомендательной системы: популярные треки, персональные рекомендации ALS, похожие треки и ранжирование кандидатов с помощью CatBoost. Основной расчёт находится в `recommendations.ipynb`. FastAPI-сервис в `recommendations_service.py` смешивает готовые рекомендации с подборкой по последним прослушиваниям.

## Подготовка окружения

Используется Python 3.9–3.11 в Linux или Python 3.11 в Windows. Курс также разрешает выполнение на своём компьютере; для этой работы используется Windows с 32 ГиБ памяти. Исходные файлы занимают около 1,3 ГБ. События обрабатываются через DuckDB с временными файлами на диске, а матрица взаимодействий собирается пакетами. Для промежуточных данных желательно оставить не менее 30 ГБ свободного места.

В Linux:

```bash
git clone https://github.com/SmesharikGPT/mle-project-sprint-4-v001.git
cd mle-project-sprint-4-v001
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m ipykernel install --user --name music-recsys --display-name 'Python (music-recsys)'
```

В Windows, из PowerShell:

```powershell
git clone https://github.com/SmesharikGPT/mle-project-sprint-4-v001.git

.\.venv\Scripts\python.exe -m ipykernel install --user --name music-recsys --display-name 'Python (music-recsys)'
```

FAISS используется для приближённого поиска кандидатов по векторам ALS. В зависимостях версии для Linux и Windows указаны отдельно. Все параметры моделей и поиска фиксированы; подбор гиперпараметров не проводится.

## Доступ к S3

Используется персональный бакет Yandex Object Storage и уже настроенные ключи в стандартной цепочке учётных данных boto3. Ключи не нужно записывать в ноутбук или репозиторий.

```bash
cp .env.example .env
```

В `.env` укажите `S3_BUCKET` и при необходимости `AWS_PROFILE`. Если используются переменные `AWS_ACCESS_KEY_ID` и `AWS_SECRET_ACCESS_KEY`, строку `AWS_PROFILE` следует убрать. Затем загрузите настройки в окружение:

```bash
set -a
source .env
set +a
```

Профиль должен иметь доступ к чтению и записи объектов в личном бакете. Перед расчётом ноутбук проверяет подключение. Локальные данные, `.env` и модели исключены из Git.

Если в Windows уже настроен CS Browser, можно пользоваться его сохранённым аккаунтом через официальный `s3browser-cli.exe`. Ключи при этом не читаются из программы и не копируются в проект. Вместо AWS-профиля задайте:

```powershell
$env:S3_BUCKET = '<имя личного бакета>'
$env:S3_BROWSER_ACCOUNT = '<имя сохранённого подключения CS Browser>'
```

По умолчанию CLI ищется в `C:\Program Files\CS Browser\s3browser-cli.exe`. Другой путь можно передать переменной `S3_BROWSER_CLI`. На Linux и без `S3_BROWSER_ACCOUNT` используется обычный boto3.

## Расчёт рекомендаций

```bash
python download_data.py
jupyter lab --no-browser
```

Откройте `recommendations.ipynb`, выберите ядро `Python (music-recsys)` и выполните все ячейки по порядку. В начале ноутбука сохранены исходники вспомогательных модулей и зависимости, чтобы его можно было перенести в Jupyter Hub одним файлом. Ячейка установки зависимостей должна выполняться до импортов.

Для последовательного запуска из терминала в активном окружении:

```bash
python run_notebook.py
```

В Windows та же команда с полным путём к интерпретатору:

```powershell
.\.venv\Scripts\python.exe -u run_notebook.py
```

Команда использует ядро `music-recsys`, выполняет ячейки с остановкой при первой ошибке и сохраняет вывод после каждой ячейки в `recommendations.ipynb`. Другое установленное ядро можно указать через `--kernel`. Отправлять на проверку нужно файл после успешного выполнения всех ячеек, с графиками и таблицей метрик.

В ноутбуке выполняются следующие шаги:

1. Проверка типов идентификаторов, обязательных полей, точных дубликатов и неизвестных атрибутов треков. Повторные прослушивания сохраняются.
2. Анализ активности пользователей, популярных треков и жанров, непрослушанных треков.
3. Сохранение подготовленных данных в S3 и повторная загрузка из S3 перед обучением.
4. Разделение событий: обучение до 16 декабря 2022 года, тест с этой даты. Ранжирование обучается на отдельном более раннем временном разбиении внутри обучающей части.
5. ALS, поиск похожих треков и ранжирование кандидатов. Для обучения ранжирования берётся воспроизводимая выборка пользователей; ограничение указано в ноутбуке. Финальные рекомендации рассчитываются для всех пользователей из событий.
6. Оценка трёх подходов на одинаковых тестовых пользователях. Определения recall, precision, coverage и novelty приведены рядом с таблицей результатов.

При рекомендации музыки разрешены повторные прослушивания. Поэтому знакомые пользователю треки не исключаются из кандидатов; новизна оценивается отдельно.

## Запуск сервиса

Запускайте команды из каталога репозитория в подготовленном выше окружении. Сервис использует `recommendations.parquet`, `top_popular.parquet` и `similar.parquet` из `data/recommendations/`. Если локальных файлов нет, он скачает их из настроенного личного S3-бакета при запуске. Пересчитывать ноутбук при каждом запуске сервиса не нужно.

```bash
python -m uvicorn recommendations_service:app --host 127.0.0.1 --port 8000
```

В Windows без активации окружения:

```powershell
.\.venv\Scripts\python.exe -m uvicorn recommendations_service:app --host 127.0.0.1 --port 8000
```

Примеры запросов из другого терминала (`curl.exe` вместо `curl` в Windows PowerShell):

```bash
curl -X POST 'http://127.0.0.1:8000/recommendations?user_id=1&k=20'
curl -X POST 'http://127.0.0.1:8000/events?user_id=1&item_id=11'
curl 'http://127.0.0.1:8000/events?user_id=1'
curl -X POST 'http://127.0.0.1:8000/recommendations?user_id=1&k=20'
curl -X POST 'http://127.0.0.1:8000/similar_items?item_id=1&k=10'
curl 'http://127.0.0.1:8000/health'
```

`POST /events` добавляет прослушанный трек. `GET /events` возвращает последние треки от нового к старому. Для очистки временной истории есть `DELETE /events?user_id=1`. Справка по API доступна по адресу `http://127.0.0.1:8000/docs`, подробности схем Parquet — в `SERVICE.md`.

### Смешивание онлайн- и офлайн-рекомендаций

Офлайн-источник — итоговые рекомендации после ранжирования, рассчитанные в первой части. Пользователь без персональной подборки получает популярные треки.

Онлайн-история хранит последние 20 разных прослушанных треков пользователя. Повторное прослушивание перемещает трек в начало. По трём последним трекам берутся до 10 соседей из `similar.parquet`. Оценка кандидата равна сумме `1 / ((позиция_события + 1) * rank_соседа)`: у более свежего события и более близкого соседа больший вес. Позиция события начинается с нуля, `rank` — с единицы. При равной оценке порядок задаёт `item_id`.

Выдача чередует онлайн- и офлайн-кандидатов, начиная с онлайн: один онлайн, один офлайн и так далее. Если один список закончился, берутся оставшиеся треки другого списка. Недостающие места заполняются популярными. Дубликаты и треки из последних 20 прослушиваний исключаются из всех источников. Без онлайн-истории сохраняется порядок персональных рекомендаций; если их мало, выдача дополняется популярными. При отсутствии подходящих треков возвращается меньше `k` рекомендаций.

Так свежие интересы влияют на ближайшую выдачу без переобучения модели. Исторические прослушивания из обучающего набора по-прежнему могут повторяться, как описано в первой части; исключение касается только недавней онлайн-истории.

Для прототипа история находится в памяти одного процесса и очищается при перезапуске. Запускать сервис нужно с одним worker, как в команде выше. Постоянное хранилище событий и работа нескольких экземпляров в эту версию не входят.

### Проверка сервиса

Сначала запустите сервис, затем в другом терминале выполните:

```bash
python test_service.py --live --url http://127.0.0.1:8000 --data-dir data/recommendations --log test_service.log --output service_test_results.json
```

В Windows:

```powershell
.\.venv\Scripts\python.exe test_service.py --live --url http://127.0.0.1:8000 --data-dir data/recommendations --log test_service.log --output service_test_results.json
```

Скрипт выбирает пользователя и треки из реальных Parquet-файлов и проверяет три сценария задания:

1. Без персональных рекомендаций и онлайн-истории — популярная выдача.
2. С персональными рекомендациями, без онлайн-истории — сохранённая офлайн-подборка.
3. С персональными рекомендациями и новыми прослушиваниями — изменившаяся смешанная выдача, содержащая онлайн- и офлайн-кандидатов.

Проверяются ответы HTTP, порядок, размер списка, отсутствие дубликатов и недавно прослушанных треков, а также API событий, похожие треки и неверные параметры. Для повторяемости тест очищает временную онлайн-историю выбранных тестовых пользователей перед проверкой и после неё. Используйте отдельный локальный экземпляр сервиса, как в примере выше.

Фактический вывод с запросами и ответами сохраняется в `test_service.log`, структурированный отчёт — в `service_test_results.json`. При успехе код завершения равен `0`, при ошибке — `1`. Оба файла включены в репозиторий.

При проверке на рассчитанных данных пройдено 17 из 17 HTTP-проверок. Для пользователя `0` добавление прослушивания трека `26` изменило выдачу на чередование 10 онлайн-кандидатов и 10 офлайн-кандидатов. После очистки истории исходная подборка восстановилась; счётчик ошибок сервиса остался равным нулю.

Отдельно можно выполнить проверки на небольших искусственных данных без S3 и запущенного сервера:

```bash
python -m unittest test_service -v
```

Все 15 модульных тестов прошли. Они проверяют логику сервиса и не заменяют оценку качества моделей на тестовом периоде.
